Answer Key & Detailed Explanations​

Part 1: Network & Security Architecture​

  1. B — ECS Task Definitions allow native secret injection from SSM Parameter Store or Secrets Manager directly into environment variables without hardcoding.
  2. B — Private subnets do not route to the public internet, preventing external bad actors from directly reaching data layers.
  3. C — Public URLs resolve to API Gateway or Load Balancers acting as security guards at the VPC boundary.
  4. B — Policies are JSON permission documents; Roles are temporary identities assumed by compute resources or users.
  5. B — User Pools manage authentication, user registration, and issue JWT tokens.
  6. B — Identity Pools exchange valid authentication tokens (JWTs) for temporary AWS IAM credentials.
  7. B — AWS WAF inspects Layer 7 HTTP payloads for web exploits like SQLi and XSS.
  8. B — AWS Shield provides automated DDoS defense at Layer 3/4 (Standard) and Layer 7 (Advanced).
  9. B — Encryption at rest scrambles physical bits stored on underlying SSDs/disks.
  10. C — KMS manages master encryption keys across AWS services.
  11. B — ECS Task Roles supply temporary IAM credentials to container instances safely.
  12. B — NAT Gateways enable private subnet instances to access the internet while blocking inbound traffic.
  13. B — NACLs are stateless firewalls at the subnet boundary.
  14. B — Security Groups are stateful firewalls at the Elastic Network Interface (ENI) level.
  15. B — Secrets Manager natively handles automatic key rotation via Lambda.
  16. C — HTTP clients pass authentication tokens via the standard Authorization: Bearer <token> header.
  17. B — API Gateway enforces stage/route throttling and burst limits to protect backends.
  18. B — Security Groups default to blocking all inbound traffic and allowing all outbound traffic.

Part 2: Compute & Microservices​

  1. A — EC2 is IaaS (you manage VMs); Fargate is serverless compute (AWS manages host infrastructure).
  2. B — ECS is a container orchestration engine for Docker containers.
  3. B — Amazon ECR is the private Docker registry service in AWS.
  4. B — ALB sends periodic HTTP health check ping requests to containers.
  5. B — ECS automatically replaces failed tasks to maintain desired task counts.
  6. B — AWS Lambda executes event-driven code without server management.
  7. B — Cold starts occur when Lambda provisions a fresh execution environment upon receiving an idle request.
  8. B — Provisioned Concurrency maintains pre-initialized execution environments.
  9. C — Lambda execution time is capped at 15 minutes max per invocation.
  10. B — Microservices must communicate via APIs or events to remain loosely coupled.
  11. B — VPC Links connect API Gateway to internal ALBs/NLBs privately.
  12. C — ALB is a Layer 7 Application Load Balancer inspecting HTTP/HTTPS headers.
  13. B — Task Definitions serve as JSON container deployment blueprints.
  14. B — ECS rolling updates launch new containers before draining old ones for zero downtime.
  15. B — Allocating more RAM to Lambda automatically allocates proportional CPU power.
  16. B — HTTP APIs are built for low latency and lower cost with subset REST features.
  17. B — Path-based routing evaluates URL request routes.

Part 3: Databases & Caching​

  1. C — DynamoDB is a fully managed NoSQL key-value/document database.
  2. A — RDS PostgreSQL provides full multi-table ACID guarantees.
  3. B — DynamoDB auto-scales storage and throughput horizontally.
  4. B — Cart operations are simple key-value lookups ideal for DynamoDB document storage and TTL.
  5. A — TTL automatically purges expired items without consuming write units.
  6. B — API Gateway Caching allocates memory at the stage edge outside the VPC.
  7. B — API Gateway Cache is a read-only HTTP response snapshot store.
  8. A — ElastiCache provides managed in-memory caching (Redis/Valkey/Memcached).
  9. A — Write-behind buffers high-speed RAM writes before background database syncing.
  10. B — SQL LIKE causes full table scans without full-text relevance or typo handling.
  11. B — Amazon OpenSearch is purpose-built for fast full-text search.
  12. B — Read Replicas replicate asynchronously, introducing potential minor replication lag.
  13. B — Aurora is AWS's high-performance MySQL/PostgreSQL compatible database.
  14. B — GSIs allow querying non-primary key attributes efficiently.
  15. B — DynamoDB hard item size limit is 400 KB.
  16. B — DECR / DECRBY execute atomic decrements in Redis.
  17. B — Expired TTL triggers a cache miss, pulling fresh data from the backend.

Part 4: Messaging & Event-Driven Design​

  1. B — Publishing 1 SNS topic event to N SQS queues is the Fan-out pattern.
  2. A — SQS queues buffer events safely during consumer outages.
  3. B — Workers must issue DeleteMessage to confirm successful processing.
  4. B — DLQs hold unprocessable "poison pill" messages for debugging.
  5. B — SQS is a transient queue; Kafka is an append-only replayable event log.
  6. B — EventBridge matches and routes events based on JSON rule criteria.
  7. B — Standard queues offer best-effort ordering; FIFO guarantees strict order.
  8. B — FIFO queues guarantee strict ordering and exactly-once processing.
  9. C — SQS message retention limit is 14 days maximum.
  10. B — AWS Step Functions orchestrates state machines and Sagas.
  11. B — Compensation transactions undo steps if subsequent Saga steps fail.
  12. B — Visibility Timeout hides in-flight messages from other workers.
  13. B — Long polling waits for messages before returning, reducing empty responses/costs.
  14. A — Schema Registry converts event structures directly into code objects.
  15. B — Default SQS Visibility Timeout is 30 seconds.
  16. B — SNS natively supports Lambda, SQS, Email, and HTTP targets.

Part 5: Storage, Frontend, & Global Delivery​

  1. B — S3 is static storage; pure SSR requires Node.js compute (Lambda/ECS).
  2. A — ISR regenerates static pages in background Lambda and updates S3/CDN.
  3. C — S3 Glacier Deep Archive offers the lowest cost archival storage.
  4. B — S3 Lifecycle Policies automate object transitions across storage tiers.
  5. B — CloudFront is AWS's global Content Delivery Network.
  6. B — CloudFront serves data from local global Edge Locations.
  7. B — Latency-Based Routing routes users to the lowest latency Region.
  8. B — Failover routing automatically redirects traffic upon health check failures.
  9. B — VPC Endpoints route traffic to AWS services internally via PrivateLink.
  10. B — Single PUT limit in S3 is 5 GB (use Multipart for larger).
  11. B — Maximum total size of a single object in S3 is 5 TB.
  12. B — S3 Versioning preserves, retrieves, and restores prior object versions.
  13. A — Presigned URLs grant temporary authenticated access to private objects.
  14. A — CloudFront integrates with ACM for free, managed SSL/TLS certificates.
  15. B — CORS headers must be enabled for cross-domain browser API calls.
  16. A — Intelligent-Tiering automatically optimizes costs for unknown access patterns.
